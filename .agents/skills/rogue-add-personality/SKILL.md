# NPC personality content

Read `docs/npc-personality.md` and `docs/npc-content-modules.md`. Feature definitions live under `WRogue/Gameplay/Npc/Content/<feature>/`; contracts are in `Contracts/`, and shared event/memory processing in `Events/`, `Memories/` and `Runtime/`. Register a trait, memory, event, goal source, capability or operator together in an `INpcContentModule`, with one composition entry in `NpcContentDefaults.cs`. Reuse a module for closely related content. `tests/scenarios/NpcRestContent.cs` demonstrates a complete extension in one file without generator/planner/AI branches or new enum values. Preserve persisted string IDs and type namespaces. Keep memories private during gameplay.

Unique-character, faction, gang, and world/story experience definitions live in `WRogue/Gameplay/Npc/Content/PersonalityWorldContent.cs`, registered by `PersonalityContent.Create()`. Extend the appropriate source table and register memories with `starting: false`; acquired traits must remain outside the starting pool. Match unique actors by the registered `Session.UniqueActors` reference, never by name or model. `FirstEncounter()` uses retained per-person memory history to prevent repeat rewards after resolution and loading. Test namesakes, line of sight, and repeated encounters.

Use `TowardFaction()` for an explicit collective memory feeling or acquired trait bias, including events without a person such as supply drops. Do not repeat the generic personal help/attack feeling in supplemental faction memories. Check `PersonalitySystem.Attitude()` and a real trade/recruitment/trust decision, plus an unrelated faction and disabled-preset boundary. Declare conflicts for incompatible faction traits and verify their skill fallback.

Publish world experiences from successful handlers in `RogueGame.Events.cs` or `RogueGame.Story.cs`; use `RogueGame.Personality.cs` for arrival/gang classification. Raid source actors must be the real leader/scout, so group history remains attributed correctly. Peaceful arrivals must use their own significant event kinds. Unspawned actors and failed arrivals must not generate memories. Per-turn visible unique encounters are scanned in `RogueGame.Flow.Turn.cs`. Add a deterministic world-handler scenario under `tests/scenarios/cases/world/` when changing these sources.

For plan changes with unchanged content IDs, bump a module-specific `catalog.Revision`; saved bindings are revalidated against the catalog fingerprint. Give a capability its desired `ResultFacts`, then register reusable `NpcOperatorSource` providers with produced facts, prerequisites and a binding callback. The composer selects providers automatically; keep physical action checks and effects in the owning content module through `NpcActionContext`. `BuildPlan` is a compatibility hook, not the normal path for new content. `npc/operator-composition` exercises a new goal composed from existing food and medicine operators.

For a lasting need, register `NpcInterestDefinition` and use the bounded `PersonalityState.RememberInterest` state. Observe the owner's real condition and known people; do not inspect unseen actors. For a shared objective, register `NpcCollectiveDefinition` with its scope, need proposal, visible listener, speech and acceptance callback. Group and faction tasks both create independent goals; faction coordination never silently changes group membership. `npc/collective-extension` exercises a new task without changes to the coordinator.

For a trait, choose `NpcPersonalityAxis` effects through `TraitEffect` that alter a real AI choice, set eligibility and conflicts in the registry, and account for item parameters when applicable. The same enum names changing dispositions; `WithEffect` can add one directly to an existing trait. To add a changing disposition, append its non-negative saved slot without renumbering the existing ones, update `NpcPersonalityAxes.DispositionCount`, add an axis class under `Gameplay/Npc/Axes/` for faction, trait and temporary need rules, memory outcomes, and a real decision; decision-only axes stay negative. Effective axes stay within −100..100. Put an event's optional `ImmediateSanity` and `RadioSanity` callbacks on its `NpcEventDefinition` in the owning module; reuse axis calculations or `NpcImmediateEmotion` helpers where suitable. These reactions change recoverable sanity, not durable experience. For a memory, choose a real `SignificantEvent`, observer/trigger conditions, evidence, eligible trait and skill outcomes, relevant disposition axis and shift, and the person/group roles and feeling change. New memories resolve after two days. `ResolveDue` randomly chooses among an eligible trait, skill, opposing trait removal, and disposition change. Check that `Report` can observe the event and that resolution uses a valid outcome. Relationship history must retain the memory after resolution and use stable actor and faction identities, including former groups.

`NpcKnowledgeSystem.ReportConfidence` decides confidence in a particular report from its evidence, source relationship and message-trust axis; that confidence is not another disposition. `NpcImmediateEmotion.Radio` dispatches the event's `RadioSanity` callback for a separate listener sanity reaction. The player has no NPC disposition axes.

The main-menu `Read Records` chronicle is an explicit viewer of saved NPC history outside gameplay. Register each significant event's payload contract, categories, readable prose and optional report prose in `NpcEventDefinition`; the records reader uses persisted metadata rather than a central kind switch. Subscribe to knowledge, relationship, goal, response or reply phases through the module. Keep creation/resolution entries and histories of removed NPCs intact. `WRogue/Engine/RecordsReader.cs` must read saves without restoring the active session or changing mods/options. Keep older archives marked partial rather than inventing missing history.

For a spoken request the player can hear, attach `NpcPlayerReply` to its event definition with a short prompt, Y/N prose and existing outcome events. Queueing and the talk action use this contract. Set `AudibleReport` for a public request whose retained fact should reach nearby listeners as hearsay. Mark meaningful speech with `IS_STORY` plus `IS_RUMOR` or `IS_REQUEST` and pass its real cause/story IDs; only an awake resident within audio range gains a heard-speech archive entry. Do not grant eyewitness memory merely because speech was audible.

The in-game V talk command and J heard journal share the `DoSay` hearing check. A player hears speech directly or overhears it, while an unseen speaker remains anonymous in `HeardJournalEntry`. For a new interaction, report its event only after it actually happens; a completed trade and a chat can add neutral contact to Shift+I without fabricating a memory.

Rumors use the fact's event location, not the speaker's current position. `Zone.BuildingAt` adds a typed building label where one exists, and otherwise leaves the district alone. Keep place colors and labels in `Zone`, faction record colors in `GameFactions`, and the archive/journal renderer in `RecordsTextColors`. Test heard wording, coloring, street fallback and saved zone kind.

For rumor chapters, radio stories and new reportable events, follow [`rogue-story-narration`](../rogue-story-narration/SKILL.md) so speech, radio, retained facts and causal wording stay aligned.

For a causal action, pass the real earlier event ID in `CauseId`; generated goals can carry multiple observed evidence IDs in `Causes`. Read Records resolves only antecedents present in the saved archive and labels goal starts `Prompted by` and other entries `Connected to`. Check the archive-only text and search with a real action, plus a missing-cause boundary. Do not infer psychological motives from traits or unrelated events; a reason must come from an actual decision rule and recorded link. If an event can be reported without custom `DescribeReport`, ensure its generic wording remains accurate.

For a trait explanation in Read Records, compare the chosen goal's actual importance with the same value evaluated while excluding that one trait. Name the trait only when this calculation yields a positive contribution; do not claim it was the sole cause of the action. Event-earned traits should have a reachable `MemoryOutcome` alongside skill fallbacks. A focused scenario may control the resolution roll to prove the real trait grant and its saved record; another scenario should exercise ordinary random outcome selection.

Pass the active `NpcContentCatalog` to goal admission, selection, completion and blocked-goal handling. Test custom content through the game's catalog; the runtime must not silently substitute the default catalog. Read Records colors archived NPC names by faction, with a neutral color for names shared across factions.

Add a deterministic named scenario in its own file under `tests/scenarios/cases/npc/`. Exercise the real event, decision, and resolution path; assert the gameplay effect and a boundary such as an unseen event, duplicate event, missing target, disabled preset, or ineligible outcome. If saved state changes, add a save/load scenario and update `docs/save-format.md`. If new production files are added, list them in `WRogue/RogueSurvivor.csproj`.

Run `sh tests/scenario.sh <name>` during development and `docker build --target test .` before finishing. Run `bash tests/e2e.sh` if startup, input, rendering, UI, or assets change. Do not restart a running game container unless the user asks.
